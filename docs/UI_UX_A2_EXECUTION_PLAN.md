## 2. 对另一份专家建议的综合取舍

以下是设计判断；具体事实校正在第 7 节，不把文档中的判断自动视为现有代码缺陷。

| 建议 | 结论 | A2.1 的落地边界 |
|---|---|---|
| 语义色、文字层级、圆角与间距规范 | 采纳 | 从本次 TV 页面涉及的资源开始；不先全量改写 main/mobile，不建立庞大的多主题框架 |
| 焦点与选中态分离 | 优先采纳 | 明亮描边表示焦点；金色短线/填充表示选中；文字/标记表示播放中；颜色不能是唯一线索 |
| 描边、缩放、阴影同时加重 | 部分采纳 | 约 2dp 描边＋可选 1.03–1.05 缩放；不强制每个控件发光/阴影，也不默认放大 1.06；优先保证不裁切、不重排 |
| 首页 Hero 与续播进度 | 采纳并约束 | 使用当前源已有信息；保证完整续播行；首页主操作“查看详情”，不预先承诺无需解析就能播放 |
| 底部 Tab 导航 | 不采纳 | 保留 A2 顶部导航；不是底栏一概错误，而是本产品不值得为此重建遥控路径 |
| 详情播放器固定 720×405dp | 不采纳固定值 | 保留小窗/全屏关系，按逻辑空间和字号适配；避免挤掉线路和选集 |
| 元信息分层、简介展开/收起 | 采纳 | 标题、必要元信息、操作、简介分层；不是每项都加 chip；不新增无真实来源的评分 |
| 集数网格＋时间线切换 | 暂缓 | 复用现有选集与 20 集分段；先减少线路/选集拥挤，不引入另一套选择模型 |
| 直播分栏、当前节目可辨识 | 采纳方向 | 保留频道/分组/EPG 的现有操作，先控制列宽、文字与焦点；不能把点播界面套到直播 |
| 直播实时毛玻璃、多日 EPG 时间轴 | 暂缓 | 不模糊正在播放的视频；多日展示必须先证实源能力、日期接口和缓存语义 |
| 搜索历史可管理、明确加载与失败 | 采纳 | 优先让已有操作可发现；无结果与网络失败分开，保留输入；不伪造热搜热度或排名 |
| 自建中英数符键盘切换 | 暂缓 | 先盘点现有键盘与输入法能力；中文输入不是加一个 Tab 就能完成 |
| 设置按任务分组、危险操作隔离 | 采纳 | 配置/外观/播放/数据/关于按实际条目归类；先改善现有结构，再判断是否需要双栏 |
| 所有设置都配图标、统一换 Material Switch | 按需 | 图标不能代替文案；开关必须验证 D-pad 操作与状态朗读；不增加第二个无意义焦点 |
| 空态、错误态和重试入口 | 提升优先级 | 这是基本可用性，不等全部视觉升级后再做；长时故障用持久面板，不只用短暂 Toast |
| 所有加载替换为骨架屏 | 部分采纳 | 已知布局可静态占位；未知时长可简洁进度＋文案；不强制扫光动画，也不认为转圈本身不专业 |
| 字体引入宋体/手写体/等宽体 | 暂缓 | 系统无衬线优先，避免包体、授权、中文回退与远距识别问题；必要时仅对时间数字验证等宽排版 |
| 启动品牌统一、国际化文案 | 采纳 | 统一底色与术语，不强制新增启动等待；字符串资源化，不向片名强行插空格 |
| 多套主题、强制 onboarding、震动 | 按最新授权拆分 | **三套暗色皮肤本期实现**，采用最小语义主题资源而非复制页面；onboarding 与震动仍不做 |

**优先级调整：焦点、可读性、空/错状态属于基础可用性；全量遗留资源 Token 化和装饰动效不是 P0；多主题按用户最新要求纳入本期。**

## 3. 新增重点：同片图片模糊氛围背景

### 3.1 视觉结构

“模糊蒙版”落实为 **模糊图片层 + 暗色遮罩层**，而不是把所有内容一起模糊。

从底到顶：

1. **兜底底色**：`#101114`，图片请求前就存在。
2. **氛围图层**：取当前影片真实 `vod_pic`，等比放大裁切覆盖氛围区域，低分辨率模糊；只保留色彩与轮廓，不要求看清海报文字。
3. **暗色与渐变遮罩**：全局压暗，文字侧与顶栏更深，底部渐隐回页面底色。
4. **前景内容**：清晰、保持比例的海报；标题、按钮、进度和焦点独立渲染，绝不进入模糊层。

| 素材/状态 | 背景 | 前景与行为 |
|---|---|---|
| 合适且清晰的横图 | A2 清晰氛围横图＋渐变遮罩 | 保持 A2 左文右图；不要求额外获取 backdrop |
| 只有竖海报，或横图不足以清晰铺满 | **同片图片模糊背景＋暗色遮罩** | 竖海报保持比例；低清前景不继续放大，必要时缩小展示 |
| 极低清但仍可解码 | 可仅用于低饱和模糊氛围 | 以前景底板和标题为主，不假装高清 |
| 无图片、请求失败或解码失败 | 稳定暗底/固定弱渐变 | 显示片名与可用操作，不模糊默认图标来冒充影片氛围 |
| 关闭影片氛围/减少动态 | 暗底，或用户明确选择的静态壁纸＋遮罩 | 卡片、焦点、播放功能不受影响 |

### 3.2 首轮调参起点（建议值，不是已验证阈值）

- 工作位图优先约 **320×180 px**；确有需要且设备验证通过时最高试到 480×270 px。与 4K 屏幕像素无须一比一匹配。
- 在工作位图尺度试验约 **8–16 px 的模糊半径**；不同算法/采样实现需重新校准，不能直接当成 Android dp 或统一平台参数。
- 全局暗色遮罩不透明度约 **55–70%**；文字区/导航区局部累计遮蔽约 **80–92%**。以最亮海报下对比度为准，不机械叠加多个固定 alpha。
- 保留少量原图色彩，饱和度约原图 **45–65%** 起步；禁止从每部海报提取颜色后改变金色强调与白色焦点。
- 焦点停留约 **250–350ms** 后才准备新氛围；若切换则淡入约 **180–250ms**。快速持键时跳过中间项，降低动态时禁用过渡。
- 首期首页按当前 Hero 影片更新，详情按当前影片更新；片库不默认每移动一张卡就换整屏背景。搜索、设置、全屏播放器保持稳定底色/视频，不铺影片模糊。

### 3.3 实现边界与性能策略

**代码事实**：`ImgUtil` 已使用 Glide，`getUrl()` 处理 Cookie/Referer/自定义请求头及 data URI；`CustomWallView` 处理共享壁纸、GIF/视频和主题取色。当前检索未找到现成模糊 Transformation；`minSdk = 24`。

因此建议：

- 复用现有图片请求模型与解码/缓存基础，不绕过 `ImgUtil.getUrl()` 另发裸 URL 请求，不为氛围请求整批影片详情。
- 扩展 TV 页面内的独立氛围层；不把“当前影片变化”写入全局壁纸设置，不触发 `RefreshEvent.theme()` 改变全应用强调色。
- 先解码小图，再在后台线程做一次静态模糊；UI 线程只切换结果。不能每帧处理截图、动态视频或整屏视图。
- 请求与页面生命周期绑定；影片/源/请求代次校验后才应用结果，旧请求不能覆盖新片。不同影片加载期间立即保留暗底，避免长时间错配上一部影片背景。
- 复用图片库的受限缓存，衍生图缓存键包含源身份/带请求头的图片模型、尺寸与变换版本；不可只按片名缓存。不得将请求头、Cookie 或完整敏感 URL 写入调试日志。
- 以当前图和过渡目标图为主；不为整排内容预生成背景、不额外解码全分辨率副本；内存紧张、后台或离页时取消任务并释放页面持有资源。
- 现有 minSdk 低于 RenderEffect 的 API 31，**不能仅靠 RenderEffect 覆盖所有设备**。优先验证现有依赖能否复用，否则在实施技术验证阶段评估小图离线变换；不为设计稿默认新增模糊库。
- 模糊不可用/内存告警时降级暗底；这不是主任务失败，不阻塞浏览和播放。

### 3.4 与用户壁纸的关系

- 影片氛围限定首页 Hero/详情背景区域，不修改已保存的自定义壁纸文件或偏好。
- 提供明确的影片氛围开关；首次安装建议启用，已有自定义壁纸用户不静默覆盖其选择。
- 当影片氛围覆盖可见区域时，不应仍在其后重复播放不可见的视频壁纸。暂停/恢复必须走既有生命周期且不影响前台播放器；这是实施前需要验证的共享边界。
- 不以“禁止重度实时模糊”为由否定本轮需求：**允许静态低分辨率同片模糊；仍禁止实时全屏玻璃效果和视频模糊。**

## 4. 页面调整基线

| 页面 | 本轮推荐 | 必须保留/补全 |
|---|---|---|
| 首页 | 顶部首页/点播/直播/收藏/搜索；片源/更多/设置可见；克制 Hero；完整续播行 | 无历史隐藏整组；没有直播配置给出解释；推送/本地仍可达 |
| 片库 | 稳定网格、清晰筛选、焦点边框、标题/备注分层 | 现有横竖/列表 Style 和大小偏好、分页与焦点恢复 |
| 详情 | 小窗、主次动作、简介按需展开、线路与选集分区；同片背景 | 不改变现有自动播放策略；全屏返回原上下文；20 集分段和换源能力 |
| 播放 | 常用控制在一级，高级控制在更多；面板文字有稳定暗底 | 进度、字幕、音轨、倍速、画面、选集、解码/引擎等能力按实际支持展示 |
| 搜索 | 输入/候选/结果层级，历史管理入口明确 | 不清空失败前输入；已有单条删除优先暴露，新增清空全部需确认及焦点恢复；不编造热度 |
| 直播 | 分组/频道/EPG 可辨识，当前播放与焦点分离，列宽受控 | 频道切换、线路、节目时间及日期能力先核验；无 EPG 明示，不造节目表 |
| 设置 | 现有项按任务归组，选中值就近可读；危险操作清楚命名 | 清缓存≠清历史≠删除配置，不能一律标同等级红色危险 |

尚未画出的搜索/直播/设置及各种空错状态，需在对应实施阶段先补规格/样张；不宣称五张 A2 图已经覆盖全应用。

## 5. 视觉与交互统一规格

- 语义资源初期最小集合：背景 `#101114`、表面 `#232429`、主文字 `#F5F3EF`、次文字 `#B7B4AE`、强调/主操作 `#D7B889`、焦点 `#F5F3EF`、主操作文字 `#101114`，另有遮罩与错误/警告语义。焦点与文字即使同色也要区分角色。
- 不把内容源徽标自动映射为“直播红”、年份映射为“信息蓝”、备注映射为“成功绿”；它们首先是元数据，而非状态。
- 优先 leanback 的 colors/dimens/TextAppearance/selector；只有确认跨 flavor 语义相同时才抽入 main。
- 960×540 逻辑参考：导航/主操作 18–20sp，标题 24–32sp，Hero 32–40sp，元信息 14–16sp。不是把 1920×1080 PNG 数字直接变成 dp；主按钮不使用 12–14sp 标签方案。
- 4/8dp 间距节奏，卡片约 8dp 圆角，面板约 12–16dp；左右约 48dp 安全区按设备调整并容纳焦点扩张。
- 正文目标对比度 ≥4.5:1，重要非文字边界/焦点目标 ≥3:1；图片遮罩后的合成效果要另测，旧版纯色对比度不等于新背景已通过。
- 方向键导航、返回、菜单必须可完成主要任务；长按删除同时提供可发现的菜单入口，破坏性操作使用明确确认/可撤销机制，不新增“再次长按”的隐藏规则。
- 弹窗关闭恢复触发控件；换源、分页、历史删除和播放返回均有合法焦点落点；不因背景异步返回而抢焦点。
- 系统无衬线、简短中文与字符串资源优先；TalkBack 校验标题、动作、播放/选中状态。无障碍是实施验收目标，不是当前认证结论。

## 6. 分阶段执行交接

用户明确要求开始实施后执行；本次文档整理不构成该授权。

| 阶段 | 任务与主要范围 | 完成条件 |
|---|---|---|
| S0 基线与技术验证 | leanback 关键页面截图/焦点路线；定位资源合并；小图模糊 API 24/31+ 验证；记录现有播放/壁纸行为 | 形成可复现基线、模糊原型结果和已知环境缺项；失败可降级，不能先改共享壁纸 |
| S1 基础体验 | leanback values、color、drawable、相关 presenter/holder；收敛语义色、文字、焦点；补关键空/错状态 | 默认/焦点/选中/禁用可辨；导航不丢；不引起 mobile 样式变化 |
| S2 首页与氛围 | `activity_home.xml`、`HomeActivity` 及 TV 背景承载；必要时最小扩展图片入口 | 两种素材布局、空源/慢源、历史进度、快速切换与模糊降级通过；生成 A2.1 更新截图 |
| S3 详情与播放控制 | `activity_video.xml`、`VideoActivity`、相关控制布局 | 小窗/全屏/返回不回归；多集/多线路/字幕音轨与高级操作仍可达 |
| S4 其余页面 | 搜索/直播/设置/收藏相关 TV 布局与 Activity | 先补页面设计，再验证历史清空、无结果、频道/EPG、设置值和危险操作 |
| S5 整体验收 | TV 构建/lint、回归、低性能真机和截图；共享改动时 mobile 回归 | 下表验证有结果与证据，不以效果图替代运行结果 |

实施应分小批可逆改动；修改既有交互前先补相应回归测试，测试设施不足时先录制可复现步骤和结果。不要把升级拆成“全仓 Token 化完成后才交付第一屏”。

### 验收矩阵

| 场景 | 通过标准/证据 |
|---|---|
| 横图/竖图/低清/缺图/失败，含极亮与高饱和图片 | 前景不变形；标题可读；亮图合成后对比度达标；无图仍可操作。逐状态截图 |
| A→B→C 快速切换、旧请求晚到、连续换源 | 最终背景属于 C 或暗底；不显示旧源图片、不抢焦点。录屏/请求代次调试记录，日志脱敏 |
| 连续浏览、页面退出/重进、内存告警 | 无崩溃/ANR/明显内存累积；图请求取消，降级正常；不在 UI 线程执行模糊 |
| 性能 | 在同设备/同源分别测开关氛围，记录帧耗时、卡顿、峰值内存与解码任务数；60Hz 设备以 16.7ms 帧预算为观察目标而非零掉帧承诺；若显著恶化则降采样/禁过渡/降级。S0 后确定设备级门槛 |
| 自定义静态/GIF/视频壁纸 | 用户偏好未丢；无不可见壁纸与前台视频无谓双播；暂停恢复不影响播放 |
| 720p/1080p/4K、大字号、长中文片名 | 不截掉主操作/进度/焦点，首屏至少完整一排可用内容；空历史时允许内容前移 |
| 方向键、返回、弹窗、删除、分页 | 核心路径无死区/焦点丢失；关闭或返回恢复合理位置；长按不是唯一入口 |
| 小窗→全屏→返回、换线路、20+ 集、字幕音轨 | 当前播放行为与基线一致，无无意重播或状态重置；无能力时说明清楚 |

### 7.2 Android 资源与 API 修正

依据本轮读取的 Android 官方资料：

- `values-light/`、`values-dark/`、`values-theme-{id}/` **不是可直接采用的 Android 资源配置目录**。系统明暗资源使用默认 `values/` 与 `values-night/`（或合法的 `notnight` 限定符）；任意主题通过 style/attr 与明确的应用逻辑组织，不能让资源系统解析自创 qualifier。
- `setTheme()` 官方要求在该 Context 实例化 View 前调用；不能承诺仅在 `App.onCreate()` 调用一次便让所有已存在 Activity/View 无需重建自动换肤。若以后做多主题，应单独设计 Activity 应用/重建或显式重绑定，并保存播放与焦点状态。本期无此需求。
- `RenderEffect` 从 API 31 才可用；不得把仅适用于新系统的实时模糊当作 minSdk 24 的统一方案。

官方依据：[资源配置限定符](https://developer.android.com/guide/topics/resources/providing-resources) · [Context.setTheme](https://developer.android.com/reference/android/content/Context#setTheme(int)) · [RenderEffect](https://developer.android.com/reference/android/graphics/RenderEffect)。

## 8. 非目标、风险与下一步

- **首期不做**：多主题引擎、手机改版、Compose 迁移、推荐后端、TMDB/额外素材服务、虚构评分、自动预告、实时视频模糊、多日 EPG 能力扩建。

- **下一步**：确认 A2.1 文档方向并明确开始实施后，从 S0 起步；先拿到模糊背景和焦点基线验证，再替换首页。尚未批准的纯详情再播放等行为变更不夹带实施。
- **本轮完成证据**：文档交叉链接和差异检查；代码事实只读核验。未运行 Android 构建、D-pad、性能或模糊实机测试；旧 A2 视觉验证不自动覆盖 A2.1。
