# 影视 TV：UI/UX 审查与候选方向

日期：2026-09-09。阶段：设计提案，**等待用户选型，不修改应用代码**。

## 结论

应用的定位是可配置、支持点播与直播的个人影视工具，不是自营内容的商业流媒体平台。专业化应优先做“内容主次、稳定对比度、遥控器状态与渐进式操作”，而不是简单换一个流行品牌色。

建议默认选择 **B 午夜蓝·内容优先**：让续播和内容出现在首屏，配置与高级能力保持可达；用稳定暗底替代依赖壁纸的对比度。A 更偏电影发现；C 更偏家庭和远距离易用。三者均为候选，不是已批准决策。通用约束见 [DESIGN.md](../../DESIGN.md)。

## 审查边界与证据等级

- **实见**：`current-emulator.png`，通过 ADB 获取的 1920×1080 首页；窗口包名为 `com.fongmi.android.tv`、页面 HomeActivity。未验证已安装包与当前 Git checkout 完全一致。
- **代码事实**：下列布局和交互代码；截图与 XML 特征相符，但不能把所有代码推断说成已完成设备测试。
- **设计判断**：优先级与改进方向，依据远距离观看、认知负担、焦点可发现性等原则。
- **未知**：其他页面的实际渲染、配置与内容变化、设备耗时、完整遥控器路径、真实观看距离。没有对整款应用给出伪精确的“专业评分”。

### 可量化的对比度证据

截图三个**无文字背景样本** `(1700,450)`、`(800,100)`、`(1100,500)` 上，假设叠加白字的对比度约为 **2.20、2.65、2.89:1**。这是壁纸亮度风险采样，不是每个现有文本控件的正式对比度测量，也不是整页无障碍认证。

三套方案的主文字/次文字对各自稳定表面计算均超过7:1；强调色按钮用深色文字，不用白字硬压亮蓝或浅金。普通文字目标4.5:1，焦点与重要边界目标3:1；图面及动态视频仍需逐帧/多场景检查。

## 值得保留的现有基础

- Leanback 遥控器模型、焦点白框与轻缩放，不需要为了时髦重写框架。
- 现有横/竖/列表风格和尺寸选择。`Product.java:13–32` 动态计算列数和宽高；不能把 XML 的初始 `80dp` 当作所有运行时海报的最终高度。
- 点播、直播、搜索、收藏、推送及高级播放功能；减少主界面干扰不等于删掉能力。
- 返回与删除模式已有明确分支（HomeActivity:468–477）；改导航时先保护这些行为。

## 三套候选方案

### A · 曜石影院
- 配色：`#101114` 背景 / `#202228` 表面 / `#F5F5F7` 主文字 / `#AFB2BA` 次文字 / `#D7B889` 强调。
- 布局：紧凑顶部导航 + 约半屏重点影片 + 完整续播行。
- 气质：克制、沉浸、偏电影感。接近高端流媒体的内容展示思路，但不复制品牌。
- 优势：视觉冲击强、主操作明确；适合以点播发现为主。
- 代价：横版图片、简介等缺失时必须自动退回普通内容行；不要把“大片Hero”作为无条件首页。
- 限制：精选影片来自真实配置内容，不虚构编辑推荐/热度榜。推送与本地文件应保留在更多/设置工具入口，示意图未展开。

### B · 午夜蓝·内容优先（推荐）
- 配色：`#0B1220` / `#172338` / `#F3F6FC` / `#A8B6CB` / `#79B8FF`。
- 布局：稳定侧导航 + 续播 + 当前内容源条目；无需先配置一张高质量大片Hero。
- 气质：清晰、理性、成熟的个人片库。
- 优势：适合外部源元信息质量不一、点播/直播/工具并存；主内容出现在更高位置。
- 代价：占用横向空间；侧栏与横向内容的焦点边界要设计清楚。
- 焦点：左边界才进入导航；右键回到当前行记忆卡片；上下跨行尽量保持列；页面选中短线不同于当前焦点白框。
- 图片说明：首页小型内容图块仅为候选构图；正式实现按源提供的横/竖图比例适配，不强裁演员脸或海报标题。

### C · 暖墨·家庭易用
- 配色：`#191816` / `#2B2925` / `#F6F1E7` / `#C0B8AC` / `#E8C58A`。
- 布局：顶部固定导航 + 大续播卡 + 直播/搜索快捷操作 + 一排收藏。
- 气质：温和、稳重、容易理解；不是亮白“护眼模式”，也不作护眼医学承诺。
- 优势：更大字号和少选项适合远距离、家庭共用；没有自动轮播干扰。
- 代价：内容曝光量少，重度浏览更依赖进入点播页。只有未配置/无历史时才替换成引导，不保留空占位。

## 按页面的设计建议

1. **首页**：品牌/当前源分层；续播第一优先；无历史整组隐藏；直播有独立易达入口；不自动换焦点或轮播。
2. **点播与筛选**：当前分类清晰；筛选折叠为摘要和可见按钮；显示生效筛选与清除；关闭后回原卡片。横/竖图适配而非强制统一裁切。
3. **详情与选集**：播放/续播为主按钮，收藏为次操作；当前线路与集数清晰；多线路、多季或上百集用分组，而不是无尽横向按钮。保留小窗功能的兼容方案待用户选择。
4. **播放控制**：常用层保留暂停、进度、选集、字幕/音轨、更多；高级层放解码、引擎、片头片尾、调试。加载失败反馈“重试/换线路/高级设置”，不是仅抛出技术错误。
5. **直播**：频道组→频道→节目顺序明确，焦点与正在播放不同；返回先关覆盖层；频道切换等待有反馈。
6. **搜索**：大输入区域、语音服务失败降级、保留键盘；区分搜索中/部分结果/无结果/源不可用；返回保留词和结果位置。不要承诺未验证的手机扫码输入能力。
7. **设置**：左分组右详情，技术名词辅以作用解释；备份/恢复/清理的影响明确；主题预览不抢占主导航。
8. **收藏/历史**：显式管理入口；删除后邻项接焦，空后回管理/返回入口；清空等破坏性操作需确认，不用隐藏手势承担唯一入口。

## 实施前后如何验收（本轮不实施）

- 批准配色与布局后，先确定首页/详情/控制层状态图，特别确认是否保留自动小窗播放。
- 先保护现有导航、返回、横竖/列表样式、换源、历史删除与播放能力，再进行资源与布局改动。
- 验收所有五向键路径：连续快速按键、跨行、进出抽屉、详情返回、删除末项、异步刷新；焦点只出现一处且不会消失。
- 验收720p/1080p/4K、大字、长中文片名、100集、多个源、空/慢/失败/缺图、无语音/无EPG/无直播配置。
- 在实际电视约3米处确认片名、字幕/音轨、进度、焦点可辨；低性能盒子验证动画和图片解码不卡顿。
- Android 源码修改后再做构建、lint及行为回归；本轮仅验证设计 SVG/PNG、预览链接与语义色对比度，不以网页静态图替代 Android 测试。

## 外部参考与适用边界

- [Android TV Layouts](https://developer.android.com/design/ui/tv/guides/styles/layouts)：960×540设计参考与48/27dp安全边距。官方搜索摘要已核实，页面全文提取失败，不扩展引述未读取内容。
- [Android TV Focus system](https://developer.android.com/design/ui/tv/guides/styles/focus-system)：缩放、边框、光晕等焦点信号；本项目不必全部叠加。
- [Netflix 2025 TV 更新说明](https://about.netflix.com/news/unveiling-our-innovative-new-tv-experience)：官方明确将 Search/My List 等入口移至顶部提高可见性，并强调选择影片所需信息。借鉴可发现性，不假定所有主流产品必须侧栏，也不引入该平台推荐系统。
- [WCAG Contrast Minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)：本提案采用其数字作为设计目标，非原生TV合规声明。
